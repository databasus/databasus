## Defects found

- Logout kept the scoped selections and both backup filters, so the next account opened the previous account's selection and filters. `publishSession` now removes them (Decision 6).
- A repeated click on the verify action of a logical backup row opened a second confirmation, and confirming both sent two `POST /verifications`. `LogicalBackupsComponent` now allows one open confirmation, as Decision 7 and the delta spec of `frontend-database-screens` describe. The test drives two clicks directly, and a real mouse double-click may rarely reach this, because the modal mask can catch the second click.

## Limitations and observations

- Item 12 follows the contract rather than the first wording of `design.md`. `startLogicalBackup` needs `WORKSPACE_VIEWER` or higher, and `logical_backup_access_test.go` lets a viewer start a backup, so a viewer keeps start, restore and download.
- Item 16 pins current behavior: `CHAIN_BROKEN` and `CANCELED` physical rows offer no action, including delete. No spec defines their row actions, so whether they need a delete stays the owner's decision.
- The `Queue check` double-click test relies on AntD's confirm button for its protection, so a one-line production change cannot break it.
- The Google Drive create test takes the token from the `draft` prop. `GoogleDriveAuthorization.test.tsx` owns the popup and asserts an update, so no single test follows the popup through to the create request.
- After a refused transfer, Retry in the transfer dialog reloads usage and workspaces and does not resend the transfer. The Transfer button resends it, and the tests pin that.
- A 200 response of another JSON shape reaches the screen through a `TypeError`, which `translateApiError` turns into the generic message. This is safe, though the body itself is not validated. An unreadable 200 body shows "(HTTP 200)" in its message and leaks nothing.
- Several tests still assert that `window.alert` was not called, although production code no longer calls it. Those assertions cannot fail, and the on-screen assertions beside them do the work.
- Three test titles in the audit below are the least exact matches: the password left empty, the error without a code or message, and the restore draft with no database identity. The new place for each states what differs.
