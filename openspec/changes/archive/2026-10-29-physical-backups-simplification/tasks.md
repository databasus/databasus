## Implementation notes

- Deleted schema-impossible scenarios: `removes orphan WAL when an in progress full has no claim` and `deletes the streamer and keeps an unrelated claim when storage changes`.
- The overlap regression failed before the live-run guard: a scheduler pass inserted a second full while the cancelled `pg_basebackup` was suspended. The cancel, delete and disable scenarios pass with the guard.
- A cancellation/completion regression exposed deletion requests for already committed files when disabling backups raced completion. The canceller now locks and reloads the row before invoking the lifecycle; the regression fails without this check and passes with it.
- The parallel API run exposed a global `pg_locks` wait in `TestPhysicalBackupTimeAfterWal`: another test database could satisfy it before this scheduler chose its timestamp. The wait now filters by its own database OID; the row-lock wait in `TestDeleteStreamingPhysicalDatabase` is isolated to its database as well.
- Compression fallback is covered through two real API backups with an isolated external command wrapper: both complete with `GZIP`, and both first request zstd. Removing the fallback loop's retry branch makes this test fail with `ERROR` instead of `COMPLETED`. Restart recovery also completes a new full after startup fails the interrupted row; scheduler lock tests cover a newly recorded mismatch as well as a newly completed full.
- The storage reference migration test checks the latest schema and was updated to use the merged table.
